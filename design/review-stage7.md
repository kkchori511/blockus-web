## 1. 중간 — 같은 버전 2인 이전 확장판 저장본이 20개·89칸으로 재개됨

- **파일:줄:** `src/game/save.ts:7`, `src/game/save.ts:19–21`, `src/engine/expansion.ts:23–28`.
- **근거:** `6fb1616`은 확장판을 20개·89칸으로 생성하고 저장 버전 2를 쓴다. `74c0438`은 Y5를 항상 제외하는 19개·84칸으로 변경했지만 저장 버전은 올리지 않았다. 로더는 버전과 종료 여부만 확인하므로 이전 규격의 `pieceSet`·`remaining`·보드·되돌리기 스냅샷을 그대로 수락한다. 새 생성기만 바꾸어서는 이어 하는 게임의 규칙이 바뀌지 않는다.
- **재현:** 이전 커밋의 생성기를 시드 0으로 실행한 세트를 버전 2의 진행 중 상태로 저장하고 현재 `loadGame()`으로 읽었다. 반환값은 null이 아니며 **20개·89칸·Y5 포함**이었다. 시작 화면에서는 똑같이 ‘블럭 확장판’으로 표시된다. 중간 커밋이 실제로 실행되거나 배포된 사용자에게 해당하며, 그 커밋을 전혀 실행하지 않았다면 기존 저장본 문제는 발생하지 않는다.
- **제안:** 저장 형식 버전과 별도로 규칙 버전을 기록하고 로드 시 세트 불변식을 확인한다. 기존 20개 판은 ‘이전 규칙’으로 명시해 그대로 이어 하게 하거나, 호환되지 않음을 알리고 새 게임을 선택하게 한다. 이미 놓인 Y5나 무작위 제외 조각을 일괄 삭제해 84칸 판으로 바꾸면 보드·점수·undo가 깨지므로 그렇게 이행하지 않는다. 최소한 이전 버전 2 확장판을 조용히 최신 규칙으로 표시하지 않아야 한다.

## 2. 중간 — 되돌리기로 탈락·완주가 취소돼도 종료 카드가 남음

- **파일:줄:** `src/ui/GameScreen.tsx:337–350`, `src/ui/GameScreen.tsx:177`.
- **근거:** 새 `out` 이벤트에서는 `banner`를 설정하지만 `undo`에서는 비우지 않는다. 엔진은 이전 보드와 `out` 배열을 복구해도 카드와 폭죽은 별도 React 상태로 남아 최대 3초 동안 취소된 결과를 표시한다.
- **재현:** 3인 확장판, 게임 시드 0에서 `chooseMove(state, 'bigFirst', createRng(13))`를 같은 RNG 인스턴스로 반복했다. 노랑의 `noMoves`가 발생한 배치 직후, 3초 이내에 그 배치를 되돌렸다. 실제 엔진 상태와 이벤트 훅을 메모리 내에서 연결해 확인한 결과, 복원된 `out`은 `[false,false,false,false]`인데 카드에는 계속 **‘노랑 · B / 더 놓을 곳이 없어요’**가 남았다. 완주를 취소하는 경우에도 같은 분기에 의해 완주 카드·폭죽이 유지된다.
- **제안:** 새 `undo`를 감지하면 활성 카드와 관련 연출을 즉시 비우고 해당 만료 타이머도 해제한다. 재시작처럼 로그가 새 게임으로 교체되는 경우에도 연출 상태를 초기화한다. ‘배치→탈락 카드→undo’ 및 ‘완주→undo’ 회귀 검증을 추가한다.

## 3. 중간 — 마지막 생존 색의 완주에는 카드·폭죽이 전혀 나오지 않음

- **파일:줄:** `src/ui/GameScreen.tsx:344–346`, `src/ui/GameScreen.tsx:201–202`, `src/ui/OutBanner.tsx:24–27`.
- **근거:** 한 상태 갱신에 `gameOver`가 있으면 모든 새 `out`을 카드 대상에서 제외한다. 폭죽은 `OutBanner` 안에서만 생성하므로 마지막 색의 `allPlaced`는 축하 연출 없이 끝난다. 결과 화면이 바로 뜬다는 의도는 주석에 있지만, 요청한 ‘색 종료 시 3초 카드, 모두 놓으면 폭죽’에는 마지막 색을 제외한다는 조건이 없다. 결과 화면의 z-index도 30으로 카드 레이어의 7보다 높아 조건만 제거해도 카드가 가려질 수 있다.
- **재현:** 3인 확장판, 게임 시드 18, 수 선택 RNG 시드 31의 bigFirst 자동 진행에서 마지막 로그는 `place(노랑,I1,(3,12)) → out(노랑,allPlaced) → gameOver`였다. 이벤트 훅 결과는 **`banner=null`**, 효과음은 `gameOver`만 발생했다. `ResultDialog`에도 별도 폭죽은 없다.
- **제안:** 완주·종료 카드와 최종 결과 화면의 표시 순서를 분리한다. 마지막 완주는 3초 연출 후 결과를 열거나, 결과 화면 자체에서 해당 색의 완주 메시지와 폭죽을 제공한다. 시간 제한과 입력은 이미 종료된 상태로 유지하고 화면 연출만 지연시킨다. 마지막 조각이 I1인 경우와 다른 조각인 경우를 모두 확인한다.

## 4. 중간 — 새 종료 알림이 스크린리더에 상태 변화로 전달되지 않음

- **파일:줄:** `src/ui/OutBanner.tsx:26–38`, `src/ui/GameScreen.tsx:177`.
- **근거:** 종료 카드는 새로 삽입되는 일반 `div`·`span`뿐이고 `role="status"`, `aria-live`, 포커스 이동이 없다. 화면의 다른 버튼에 포커스가 있는 사용자는 누가 종료·완주했는지 자동으로 전달받을 수 없다. 알림은 3초 뒤 사라지고, 효과음만으로는 색·이름·종료 사유를 알 수 없다. 음소거 상태에서는 그 소리도 없다.
- **재현 경로:** 키보드로 조작 버튼에 포커스를 둔 채 배치해 다른 색이 탈락하거나 완주하게 한다. 생성되는 종료 알림 DOM에 라이브 리전이 없고 포커스도 옮기지 않는 것을 코드로 확인했다. 실제 스크린리더 실행 검증은 수행하지 않았다.
- **제안:** 게임 화면에 항상 존재하는 `role="status" aria-live="polite" aria-atomic="true"` 영역을 두고, 새 이벤트마다 ‘노랑, B, 더 놓을 곳이 없어 종료’처럼 텍스트를 갱신한다. 시각 카드와 분리하면 애니메이션 종료 시점을 접근성 알림의 수명과 분리할 수 있다. 폭죽 컨테이너는 장식이므로 `aria-hidden="true"`로 표시한다. 알림 때문에 다음 플레이어의 포커스를 빼앗지는 않는다.

## 5. 낮음 — 연속된 종료 이벤트가 앞 카드의 3초 노출을 잘라 버림

- **파일:줄:** `src/ui/GameScreen.tsx:346–349`, `src/ui/GameScreen.tsx:177`.
- **근거:** 같은 배치에서 발생한 여러 `out`은 하나의 `items`로 묶지만, 서로 다른 배치에서 생긴 종료는 기존 카드를 즉시 새 카드로 교체한다. `key={banner.id}` 때문에 앞 카드와 폭죽도 즉시 언마운트된다. 이전 타이머가 새 카드를 지우지 않도록 하는 id 검사는 적절하지만, 앞 카드의 표시 시간을 보장하지는 않는다.
- **재현:** A 색 종료 카드가 뜬 후 다음 플레이어가 1초 안에 배치해 B 색도 종료되도록 한다. A 카드는 3초를 채우지 못하고 사라진다. 카드가 입력을 막지 않으므로 정상적인 빠른 플레이에서도 가능한 경로다.
- **제안:** 종료 알림을 큐에 넣어 카드마다 3초씩 보여 주거나, 활성 카드에 새 종료 항목을 합치고 표시 시간을 다시 계산한다. 합치는 정책이면 기존 항목과 새 항목의 최소 노출 시간을 정의한다. 앞 이벤트를 건너뛰고 최신 이벤트만 보여 주는 것이 의도라면 ‘각 색 3초 카드’ 요구와 먼저 일치시켜야 한다.

## 6. 낮음 — 3인 공용 초록의 완주에도 획득 점수처럼 +15/+20이 표시됨

- **파일:줄:** `src/ui/GameScreen.tsx:361–365`, `src/ui/OutBanner.tsx:35–37`.
- **근거:** `bannerItem()`은 소유자가 `'shared'`인 경우 이름만 ‘공용’으로 바꾸고, 보너스 계산은 일반 색과 동일하게 한다. 숨김이 꺼져 있고 초록의 마지막 조각이 I1이면 반환되는 항목은 `who='초록 · 공용', bonus=20`이다. 카드에는 공용 색은 점수 제외라는 설명이 없어 실제로 누군가에게 가산되는 점수처럼 보인다. 최종 플레이어 점수 집계 자체는 초록을 제외하므로 산술 오류가 아니라 새 카드의 규칙 전달 오류다.
- **재현:** 3인·숨김 해제 상태에서 초록을 완주한다. 마지막이 I1이면 +20, 아니면 +15 배지가 나타난다. 해당 분기는 순수 함수 호출로 확인했다.
- **제안:** `owner === 'shared'`이면 `bonus=null`로 하고 필요하면 ‘공용 색 · 점수 제외’를 표시한다. 완주 메시지와 폭죽은 일반 색처럼 유지할 수 있다.

## 7. 낮음 — 동작 줄이기 설정에서도 종료 카드의 확대·축소가 계속됨

- **파일:줄:** `src/index.css:464`, `src/index.css:508–527`, `src/index.css:559–563`.
- **근거:** `prefers-reduced-motion: reduce`에서는 `.confetti`만 숨긴다. 종료 카드는 여전히 `scale(0.6) → scale(1.06) → scale(1) → scale(0.96)` 애니메이션을 실행한다. 폭죽을 줄여도 화면 중앙에서 갑자기 확대되는 큰 카드의 움직임은 남는다.
- **재현 경로:** OS의 동작 줄이기를 켜고 종료 이벤트를 발생시킨다. CSS상 `.out-banner` 애니메이션을 덮어쓰는 규칙이 없어 같은 transform 애니메이션이 선택된다. 브라우저 시각 검증은 수행하지 않았다.
- **제안:** 해당 미디어 쿼리에 `.out-banner { animation: none; transform: none; opacity: 1; }`을 추가하는 방향을 권장한다. 현재 JavaScript 타이머가 3초 뒤 요소를 제거하므로 CSS 애니메이션을 꺼도 카드가 영구 잔류하지 않는다.

## 오류로 분류하지 않은 확인 사항

- **확장판 규칙:** 1,000개 시드 모두 중복 없는 19개·84칸, T6·C6·H6·S6 필수, Y5 제외, 5칸 7개·4칸 4개·1~3칸 4개였다. 합계는 `89 + 24 - 5 - (4×5) - 4 = 84`로 맞는다. 네 색은 동일한 세트를 받는다. 기존 classic/allRandom은 `PIECE_IDS` 21개를 유지한다.
- **새 6칸 조각:** 정의상 각 조각은 6칸이고 연결돼 있다. 기존 테스트가 방향 변형의 중복 여부와 모든 인원·모드의 게임 종료를 확인한다. 이번 비교에서 조각 구성이나 엔진 점수 계산의 추가 오류는 발견하지 못했다.
- **숨김 옵션:** `bannerItem()`의 숫자 보너스는 `!hideRemaining` 조건으로 차단되며, 숨김을 켠 함수 검증에서 `bonus=null`이었다. 기존 패널도 진행 중 숫자 점수를 `—`로 표시한다. 완주 사실과 폭죽은 요청된 종료 알림 자체이므로 이를 숫자 점수 노출 버그로 분류하지 않았다. DOM·JavaScript 내부 상태를 숨기는 보안 기능이라는 의미는 아니다.
- **main의 버전 1 저장본:** 버전 2 로더는 dailySet뿐 아니라 classic/allRandom의 버전 1 저장본도 모두 거부한다. classic 상태로 검증한 결과도 null이었다. 이는 기존 저장본을 무시한다는 코드 주석 및 요청된 버전 상승에 따른 **명시적 비호환 동작**이어서 별도 버그 건수에는 포함하지 않았다. 다만 배포 시 ‘이어서 하기’가 없어짐을 알려야 하며, 기존 게임 보존이 제품 요구라면 classic/allRandom 선택 이행이 필요하다.
- **이전 시작 설정:** 저장된 `mode='dailySet'`은 classic으로 바뀌고 인원·이름·타이머·숨김·undo 옵션은 유지됐다. 해당 fallback은 동작한다. 삭제된 모드를 expansion으로 자동 재해석하지 않는다.
- **효과음:** 블럭 선택·회전·뒤집기는 상태 updater 밖에서 재생하므로 React가 updater를 재실행하는 데 따른 이중 재생을 만들지 않는다. Web Audio 모의 객체에서 세 조작의 oscillator 6개가 모두 종료 시각을 예약했고, 음소거 후 호출은 새 노드를 만들지 않았다. 실제 음량·음색·기기별 오디오 정책은 검증하지 않았다.
- **성능:** 폭죽은 한 번에 최대 140개이며 난수 생성은 마운트 시 한 번이다. CSS 애니메이션은 transform/opacity를 변경한다. 반복 렌더마다 입자를 다시 생성하거나 매 프레임 React 상태를 바꾸는 루프는 없다. 새 변경에서 확정적인 성능 결함을 발견하지 못했으나 실제 태블릿 프레임 성능은 측정하지 않았다.
